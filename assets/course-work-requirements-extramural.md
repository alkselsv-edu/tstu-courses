# Требования к курсовой работе (заочники)

## Инструменты и технологии

Фронтенд:

- Шаблонизатор Pug или Jinja

Бэкенд:

- Fastify или FastAPI
- PostgreSQL или MySQL

## Функциональные требования

Проверяется по работающему приложению (без доработки «на защите»).

### Общие

- В предметной области есть не менее двух связанных сущностей (связь 1:N или M:N видна в интерфейсе и в данных)
- Реализованы операции создания, чтения, обновления и удаления минимум для одной сущности предметной области; для второй — хотя бы чтение списка и создание или редактирование
- Есть поиск или фильтрация списка хотя бы для одной сущности
- Данные после перезагрузки страницы и перезапуска сервера сохраняются (источник истины — БД)



### Фронтенд (Pug / Jinja)

- Есть страницы со списками и формами создания/редактирования сущностей
- Формы проверяют обязательные поля; при ошибке пользователь видит сообщение на странице
- Создание, изменение и удаление выполняются через запросы к серверу, а не только в памяти процесса
- В приложении не менее трёх страниц (например: список, форма создания/редактирования, детальная страница или отдельный список второй сущности)



### Бэкенд

- Все сущности хранятся в PostgreSQL или MySQL; схема создаётся/обновляется миграциями
- Входящие данные валидируются на сервере; при невалидном запросе пользователь получает понятную ошибку (страница с сообщением или код 4xx)
- Сервер обрабатывает создание, чтение, обновление и удаление сущностей предметной области согласно пунктам выше



## Нефункциональные требования

Фронтенд:

- Весь код разбит на модули
- Код документирован

Бэкенд:

- Весь код разбит на модули
- Использование ORM
- Код документирован



## Артефакты сдачи

1. Репозиторий на GitHub с полной историей коммитов
2. README с:
  - кратким описанием темы и стека
  - инструкцией запуска (приложение + БД)
  - `.env.example` (без секретов)
  - командами миграций
  - учётными данными демо-пользователя (если нужны)
3. Пояснительная записка
4. Демо — одно из:
  - короткое офлай-демо (3–5 мин): просмотр списков → создание/редактирование → поиск/фильтр
  - или онлайн-демо
5. Ссылка на репозиторий в форме сдачи

Не сдавать: архивы без git, только скриншоты без запускаемого кода.

## Критерии приёмки

Работа не принимается, если не выполняется хотя бы одно:


| №   | Критерий                                                                       |
| --- | ------------------------------------------------------------------------------ |
| 1   | Проект запускается                                                             |
| 2   | Есть ≥ 2 связанных сущностей, связи видны в интерфейсе                         |
| 3   | CRUD минимум для 1 сущности; для второй — список и создание или редактирование |
| 4   | Есть поиск или фильтрация                                                      |
| 5   | Данные хранятся в БД; схема через миграции                                     |
| 6   | ≥ 3 страниц; валидация форм и понятные ошибки                                  |
| 7   | Стек из разрешённого списка (Pug/Jinja + Fastify/FastAPI + PostgreSQL/MySQL)   |
