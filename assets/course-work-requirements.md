# Требования к курсовой работе

## Инструменты и технологии

Фронтенд:

- NPM или Yarn
- React (функциональные компоненты и хуки)
- React Router
- Vite (допускается Webpack)
- Управление состоянием: Redux Toolkit или Zustand
- Работа с API: RTK Query, TanStack Query (React Query) или отдельный модуль/класс API-клиента

Бэкенд (на выбор один стек):

- Node.js: Fastify + PostgreSQL или MySQL (доступ к БД через ORM или query-библиотеку, например Slonik)
- Python: FastAPI + SQLAlchemy + PostgreSQL или MySQL
- Go *(допустимо):* веб-сервер на Go + GORM + PostgreSQL или MySQL

## Функциональные требования

Проверяется по работающему приложению.

### Общие

- В предметной области есть не менее трёх связанных сущностей (связь 1:N или M:N видна в UI и в API; пользователь тоже считается сущностью, если с ним связаны данные)
- Реализованы операции создания, чтения, обновления и удаления минимум для двух сущностей предметной области
- Есть поиск или фильтрация списка хотя бы для одной сущности
- Данные после перезагрузки страницы и перезапуска сервера сохраняются (источник истины – БД)



### Фронтенд

- Все формы создания/редактирования – управляемые, с валидацией до отправки (обязательные поля, базовые форматы); ошибки показываются пользователю
- Создание, изменение и удаление выполняются через запросы к API, а не через локальное состояние или `localStorage`
- Реализованы регистрация и вход; после успешного входа клиент получает JWT и сохраняет его (например, в `localStorage` или памяти приложения)
- Запросы к защищённым эндпоинтам отправляются с заголовком `Authorization: Bearer <token>`
- Защищённые страницы/действия недоступны без валидного JWT-токена (редирект на вход или сообщение об ошибке)
- Пока ожидается ответ сервера, отображается индикатор загрузки; при ошибке API пользователь видит понятное сообщение
- В приложении не менее трёх маршрутов/страниц (например: вход/регистрация, список, карточка или форма)



### Бэкенд

- Для сущностей предметной области есть HTTP API минимум с операциями чтения списка, чтения одной записи, создания, обновления и удаления (где удаление уместно)
- Все сущности хранятся в PostgreSQL или MySQL; схема создаётся/обновляется миграциями
- Входящие данные валидируются на сервере; при невалидном запросе возвращается код 4xx и описание ошибки
- Реализованы регистрация и аутентификация по JWT: при входе сервер выдаёт токен, защищённые маршруты принимают `Authorization: Bearer <token>` и отклоняют запросы без токена или с невалидным/истёкшим токеном (401)
- Пароли не хранятся в открытом виде
- Запросы на изменение чужих данных отклоняются (проверка владельца/прав по данным из JWT), даже если id подставлен вручную



## Нефункциональные требования

Фронтенд:

- Весь код разбит на модули
- Запросы к бэкенду расположены в одном месте: RTK Query, TanStack Query или отдельный модуль/класс API-клиента
- *Есть тесты (будет плюсом)*
- Код документирован

Бэкенд:

- Весь код разбит на модули
- Использование подсказок типов (для FastAPI и Go)
- Использование ORM или query-библиотеки для работы с БД
- *Есть тесты (будет плюсом)*
- Код документирован



## Артефакты сдачи

1. Репозиторий на GitHub с полной историей коммитов
2. README с:
  - кратким описанием темы и стека
  - инструкцией запуска (фронтенд + бэкенд + БД)
  - `.env.example` (без секретов)
  - командами миграций
  - учётными данными демо-пользователя (если нужны)
3. Пояснительная записка по [примерному содержанию](course-work-outline.md)
4. Демо – одно из:
  - короткое офлайн-демо (3–5 мин): регистрация → CRUD → фильтр/поиск → выход
  - или онлайн-демо
5. Ссылка на репозиторий в форме сдачи

Не принимаются: архивы без git, только скриншоты без запускаемого кода.

## Критерии приёмки

Работа не принимается, если не выполняется хотя бы один критерий:


| №   | Критерий                                                               |
| --- | ---------------------------------------------------------------------- |
| 1   | Проект запускается                                                     |
| 2   | Есть ≥ 3 связанных сущностей, связи видны в UI и API                   |
| 3   | CRUD минимум для 2 сущностей предметной области                        |
| 4   | Есть поиск или фильтрация                                              |
| 5   | JWT: регистрация, вход, `Bearer`, 401 без токена                       |
| 6   | Чужие данные нельзя изменить подстановкой id                           |
| 7   | Пароли не в открытом виде; схема через миграции                        |
| 8   | ≥ 3 маршрута; загрузчик данных и сообщения об ошибках API              |
| 9   | Стек из разрешённого списка (React + RTK/Zustand + Fastify/FastAPI/Go) |
